# CMS (Sanity) — импорт контента с оригинала

Здесь: схемы контента (`schemaTypes.js`) и скрипт импорта (`import.mjs`),
который тянет всех **врачей, болезни, отзывы, новости** из WordPress-API
старого сайта и заливает в твой проект Sanity (`ogu6ewxe`).

## 0. Что нужно один раз
- Установить **Node.js LTS**: https://nodejs.org (кнопка LTS).
- Иметь **новый API-токен Sanity** (с правом Editor). В чат его не вставляем.

## 1. Создать Sanity Studio (редактор для клиента)
В отдельной папке (не в этом репозитории):
```bash
npm create sanity@latest -- --project ogu6ewxe --dataset production
```
Выбрать: **Clean project with no predefined schemas**, TypeScript — No.
Затем скопировать `schemaTypes.js` из этой папки в студию и подключить:
в `sanity.config.js` → `schema: { types: schemaTypes }` (импортом из файла).
Проверить локально: `npm run dev` (студия на http://localhost:3333).
Опубликовать редактор для клиента: `npx sanity deploy` → адрес вида `assuta.sanity.studio`.

## 2. Запустить импорт (заливает контент в Sanity)
В КОРНЕ этого репозитория:
```bash
npm install
# создать .env.local (он в .gitignore) и вписать токен:
#   SANITY_API_TOKEN=твой_новый_токен
node --env-file=.env.local cms/import.mjs
```
Скрипт напечатает, сколько врачей/болезней/отзывов/новостей залито.
Повторный запуск безопасен — документы обновляются (createOrReplace), дубликатов нет.

## 3. Проверить
Открой Sanity Studio (локально или задеплоенную) — там появятся все врачи,
болезни (с текстами и фото), отзывы, новости.

## Мгновенное обновление сайта после правок в Studio

Без этой настройки правки появляются на сайте в течение пяти минут
(страховочный интервал). С вебхуком — за секунды.

### 1. Придумать секрет

Любая длинная случайная строка, например из 32 символов. Одно и то же
значение понадобится в двух местах.

### 2. Прописать секрет на хостинге

Timeweb → приложение → Настройки деплоя → Переменные:

| Имя | Значение |
|---|---|
| `REVALIDATE_SECRET` | придуманная строка |

Сохранить и дождаться пересборки.

### 3. Создать вебхук в Sanity

1. Открыть **sanity.io/manage** → проект `ogu6ewxe`
2. Вкладка **API** → раздел **Webhooks** → **Create webhook**
3. Заполнить:

| Поле | Значение |
|---|---|
| Name | Обновление сайта |
| URL | `https://assuta.org/api/revalidate` (до переключения домена — технический адрес Timeweb) |
| Dataset | production |
| Trigger on | Create, Update, Delete |
| Filter | `_type in ["doctor","disease","news","review"]` |
| HTTP method | POST |
| HTTP Headers | имя `x-revalidate-secret`, значение — тот же секрет |
| Projection | `{_type, "slug": slug.current}` |

4. Сохранить.

### 4. Проверить

Изменить что-нибудь в Studio и опубликовать. Через несколько секунд
обновить страницу на сайте — правка должна быть на месте.

Если не сработало: в Sanity у вебхука есть журнал доставок, там видно
код ответа. `401` означает, что секрет в вебхуке и в переменной Timeweb
не совпадают.

## Перевод контента на английский

### Как устроено

В схеме у каждого переводимого типа рядом с русским полем лежит английское:

| Тип | Русское поле | Английское |
|---|---|---|
| Заболевание | `title`, `excerpt`, `bodyHtml` | `titleEn`, `excerptEn`, `bodyHtmlEn` |
| Врач | `name`, `specialization`, `bodyHtml` | `nameEn`, `specializationEn`, `bodyHtmlEn` |
| Новость | `title`, `excerpt`, `bodyHtml` | `titleEn`, `excerptEn`, `bodyHtmlEn` |

Сайт на английской версии берёт поле `…En`, если оно заполнено, иначе показывает
русское. Пустых мест на странице не будет, даже пока перевод не готов.

Направления (`department` у врача, `category` у заболевания) на английский
в базе **не переводятся**: по этим значениям сайт собирает врачей и статьи
в разделы, поэтому они должны оставаться одинаковыми. Английские подписи для них
лежат в `data/site.js` (функция `cmsLabel`).

### Заливка переводов

Переводы лежат в `cms/i18n-translated.json`. Залить:

```
node cms/i18n-import.mjs --dry     примерка, ничего не пишет
node cms/i18n-import.mjs           запись
```

Токен — только через окружение, в коде его нет:

```
$env:SANITY_API_TOKEN="..."
node cms/i18n-import.mjs
```

После работы закрой окно PowerShell, чтобы токен не остался в сессии,
и отзови токен в Sanity, если он больше не нужен.

**Заполненные вручную английские поля скрипт не трогает.** Клиника может править
переводы в Studio — повторный запуск их не перезапишет. Флаг `--force` снимает
эту защиту, если нужно намеренно перезалить.

Файл можно заливать по частям: обрабатывается ровно то, что в нём лежит.

### Выгрузка нового контента на перевод

Когда в CMS появятся новые статьи:

```
node cms/i18n-export.mjs
```

Скрипт читает базу, пропускает всё, что уже переведено, и складывает остальное
в `cms/i18n-source.json` вместе со счётчиком знаков. Ничего не меняет.

### Поля в Studio

Новые поля появятся в Studio только после того, как туда попадёт обновлённая
схема из `cms/schemaTypes.js` и Studio будет передеплоена (`npx sanity deploy`).
