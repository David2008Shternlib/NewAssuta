# Редактор контента (Sanity Studio)

Редактор — отдельный маленький проект, **не часть сайта**. Сотрудники клиники
заходят в него и правят врачей, заболевания, новости и отзывы. Сайт и редактор
смотрят в одну базу (проект Sanity `ogu6ewxe`, датасет `production`).

## Адреса

| Что | Адрес |
|---|---|
| **Редактор контента** (для сотрудников) | https://assuta.sanity.studio |
| Управление проектом (участники, токены, тарифы) | https://www.sanity.io/organizations/o2cOGT4RC/project/ogu6ewxe |
| Папка редактора на компьютере | `C:\Projects\assuta-studio` |

Не перепутать: управление проектом — это администрирование, карточки врачей
и статьи там не редактируются.

Редактор уже выложен. Из панели организации он открывается ещё и по длинной
внутренней ссылке вида `sanity.io/@o2cOGT4RC/studio/sggaafuplihu0kvffoiq9wlq/...` —
это тот же редактор. Сотрудникам давать короткий адрес.

Файлы в этой папке (`cms/studio`) — копии конфигурации редактора, лежат здесь
на случай, если папка редактора потеряется. Править нужно оригиналы
в `C:\Projects\assuta-studio`, а не эти копии.

## Обновить редактор после изменения схемы

Схема — это список полей в карточках. Она лежит в двух местах:

| Где | Зачем |
|---|---|
| `C:\Projects\newAssuta\cms\schemaTypes.js` | исходник, хранится вместе с сайтом |
| `C:\Projects\assuta-studio\schemaTypes\index.js` | рабочая копия редактора |

Когда исходник меняется, копию нужно обновить и редактор выложить заново:

```powershell
Copy-Item C:\Projects\newAssuta\cms\schemaTypes.js C:\Projects\assuta-studio\schemaTypes\index.js -Force
cd C:\Projects\assuta-studio
npm install
npx sanity deploy
```

Адрес редактора при этом не меняется — обновляется то же приложение.

На данные изменение схемы не влияет: база принимает поля независимо от
редактора, и сайт показывает их сразу. Публикация нужна только для того,
чтобы поля стали видны и редактируемы руками.

## Посмотреть у себя, не выкладывая

```powershell
cd C:\Projects\assuta-studio
npm run dev
```

Откроется http://localhost:3333. Остановить — Ctrl+C.

## Как дать доступ новому сотруднику

1. Зайти в управление проектом (ссылка выше)
2. Вкладка **Members** → **Invite members**
3. Ввести рабочую почту сотрудника, роль **Editor**
   (Editor правит контент, но не может менять настройки проекта и выдавать токены)
4. Сотрудник получит письмо, заведёт аккаунт и зайдёт по ссылке на редактор

Увольняется сотрудник — там же, в Members, удалить его из проекта.

Токены (Settings → API → Tokens) сотрудникам не выдаются. Они нужны только
для скриптов и дают доступ в обход интерфейса и ролей.
