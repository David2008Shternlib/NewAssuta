## 1. Как мы разворачиваем сайт на Timeweb

Timeweb Cloud App Platform умеет собирать Next.js прямо из GitHub. Ключевой момент:
**при создании приложения нужно включить переключатель «Поддержка SSR»**.

Тогда приложение становится backend-приложением: выбирается конфигурация сервера,
проект собирается командой `npm run build` и запускается `npm start`.

> **Важно:** отключить или включить SSR после создания приложения нельзя.
> Если создать без SSR — придётся удалять приложение и делать заново.
> Без SSR не будут работать: `/en`-маршруты, приём заявок (`/api/lead`),
> автоподтягивание контента из CMS без пересборки.

### Что уже подготовлено в коде

| Настройка | Где | Зачем |
|---|---|---|
| `start: next start -H 0.0.0.0` | `package.json` | чтобы приложение слушало внешний интерфейс контейнера |
| `engines.node >= 18.18` | `package.json` | Timeweb подберёт подходящую версию Node |
| `poweredByHeader: false`, `compress: true` | `next.config.mjs` | убрали лишний заголовок, включили сжатие |
| Заголовки безопасности | `next.config.mjs` | HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy |
| 301-редиректы со старых адресов | `next.config.mjs` | сохраняем позиции в поиске |

### Переменные окружения, которые нужно задать в панели Timeweb

| Переменная | Значение | Обязательна |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://assuta.org` | да |
| `TELEGRAM_BOT_TOKEN` | токен бота | для заявок |
| `TELEGRAM_CHAT_ID` | id чата/группы | для заявок |
| `NEXT_PUBLIC_SANITY_PROJECT_ID` | `ogu6ewxe` | нет (есть в коде) |
| `NEXT_PUBLIC_SANITY_DATASET` | `production` | нет (есть в коде) |

**Токены вводятся только в панели Timeweb. Ни в коде, ни в репозитории, ни в переписке.**

### Настройки приложения в панели

- Репозиторий: наш GitHub, ветка **`main`**
- Автодеплой: включить (каждый push в `main` = обновление сайта)
- Команда сборки: `npm run build`
- Команда запуска: `npm start`
- Путь проверки состояния (healthcheck): `/`
- Домен: сначала технический адрес Timeweb, затем `assuta.org` + бесплатный SSL

## 2. График на 2 недели

### Неделя 1 — довести сайт и развернуть на Timeweb

**Дни 1–2. Инфраструктура**
- Дэвид: создаёт приложение в Timeweb Cloud с **включённым SSR**, подключает GitHub, ветку `main`
- Дэвид: вводит переменные окружения
- Я: сливаю ветку `designTest` в `main`, проверяю сборку
- Результат: сайт открывается по техническому адресу Timeweb

**Дни 3–4. Оформление контента из CMS**
- Я: привожу в порядок вёрстку статей о заболеваниях и врачах (сейчас это «сырой» HTML со старого сайта — заголовки, списки, таблицы, изображения)
- Я: чищу мусорную разметку, оставшуюся от WordPress
- Результат: страницы заболеваний выглядят так же аккуратно, как остальной сайт

**Дни 5–6. Заявки и аналитика**
- Дэвид: создаёт Telegram-бота (`@BotFather`), получает токен и id чата, вводит в Timeweb
- Я: проверяю приём заявок со всех форм, добавляю уведомление об ошибке отправки
- Дэвид/клиент: решает по Яндекс.Метрике — заводить новый счётчик или использовать существующий
- Результат: заявки падают в Telegram, статистика собирается

**День 7. Внутренняя проверка**
- Я: полный прогон — все страницы, мобильная версия, тёмная тема, EN-версия, битые ссылки, скорость
- Я: список найденного и исправления

---

### Неделя 2 — контент клиента, домен, сдача

**Дни 8–9. Материалы от клиента**
- Заполняем страницы реальными данными клиента (см. раздел 3)
- Я: правлю тексты, юридические страницы, контакты

**Дни 10–11. Финальная проверка качества**
- Проверка SEO: карта сайта, метаданные, редиректы со всех старых адресов
- Проверка доступности для аудитории 60+: размер шрифта, контраст, размер кнопок
- Проверка безопасности: HTTPS, заголовки, защита форм от спама
- Проверка скорости загрузки

**День 12. Показ клиенту**
- Сайт на техническом адресе Timeweb + презентация
- Собираем правки клиента

**День 13. Правки по итогам показа**

**День 14. Переключение домена**
- Клиент переводит `assuta.org` на Timeweb (меняет A-запись / NS)
- Выпускаем SSL
- Проверяем редиректы со старых адресов и индексацию
- Старый сайт **не удаляем** — оставляем как резерв на пару недель

## 3. Что нужно от клиента (нужно запросить как можно раньше)

Это единственное, что может сорвать срок — всё остальное в наших руках.

| Что | Зачем | Критичность |
|---|---|---|
| Доступ к домену `assuta.org` (или контакт того, кто им управляет) | переключить сайт в день 14 | критично |
| Доступ в аккаунт Timeweb (или чтобы завели и дали нам) | развернуть сайт | критично |
| Актуальные телефоны, адрес, email, реквизиты | контакты на сайте | критично |
| Юридические тексты: политика конфиденциальности, согласие на обработку данных | требование закона для форм | критично |
| Куда отправлять заявки (Telegram-чат / почта / CRM) | форма заявки | критично |
| Цены на программы диагностики | страница диагностики | важно |
| Подтверждение, что отзывы можно публиковать | страница отзывов | важно |
| Сертификаты, лицензии, аккредитации | блок доверия | важно |
| Врач-эксперт, который заверит медицинские тексты | требование поисковиков к медицинским сайтам | важно |
| Решение по онлайн-чату (Jivo) и по счётчику Яндекс.Метрики | подключение в одну строку | отложено |

## 4. Что сознательно откладываем

- **Онлайн-чат в отдельном окне (Jivo)** — по решению клиента. Код уже готов, включается одним значением в настройках.
- **Перевод статей на английский** — интерфейс на английском, тексты статей русские (как и на оригинальном сайте). Перевод 149 статей — отдельная работа.
- **ИИ-помощник вместо чата** — обсуждали, вернёмся после запуска.

## 5. Риски и запасные варианты

| Риск | Вероятность | Что делаем |
|---|---|---|
| Клиент затянет с доступом к домену | высокая | Сдаём на техническом адресе Timeweb, домен переключаем позже — работа считается выполненной |
| Клиент не даст юридические тексты | средняя | Готовим типовые шаблоны, клиент только утверждает |
| Приложение создали без SSR | средняя | Удалить и создать заново — потеря полдня, поэтому проверяем переключатель дважды |
| Что-то сломается после переключения домена | низкая | Старый сайт оставляем включённым, откат = вернуть старую A-запись |
| Timeweb-тариф не потянет нагрузку | низкая | Тариф меняется в панели за минуты |

## 6. Как выглядит рабочий процесс после запуска

1. Клиент правит контент сам в редакторе Sanity (адрес в `cms/studio/README.md`) — сайт обновляется автоматически, без нас.
2. Правки в коде: я пишу изменения → Дэвид отправляет через GitHub Desktop → Timeweb сам пересобирает сайт.
3. Заявки приходят в Telegram.
4. Статистика — в Яндекс.Метрике.
